# 남욱 프로세스

사용자 요청을 검증하고 변경 시나리오를 합의한 뒤 구현과 독립 리뷰를 별도 담당자에게 맡겨 실제 결과를 완료 기준과 대조하는 플러그인입니다.

## 작업 흐름

1. 메인이 [요청 검증과 구현 위임](skills/request-to-implementation/SKILL.md)에 따라 원하는 변화·대상·제약·완료 판단 방향을 사전 검토에 전달할 만큼 이해합니다. 사용자만 정할 결정을 질문하고 미정 구현 상세는 조사 질문으로 넘깁니다. 설명·분석만 요청한 경우 메인이 처리합니다.
2. 구현 전 검토 전용 서브에이전트가 [변경 검토](skills/change-review/SKILL.md)를 읽고 요청의 전제를 실제 코드·설정·호출 흐름·실행 환경과 대조합니다. 실행 가능성과 제약, 변경 시나리오와 기존 계약 유지·확장변경·미확인 판단 및 근거를 반환합니다.
3. 메인은 근거를 대조해 변경 전후 흐름, 보존 대상, 호출자·데이터 영향과 검증 계획을 사용자에게 설명합니다. 계약 유지안은 구현 승인을 받고, 계약 확장·변경안은 대안과 이행 정책까지 합의한 뒤 구현 승인을 받습니다. 판단을 막는 미확인에 의존하는 구현은 보류합니다.
4. [작업 명세](skills/request-to-implementation/references/task-brief.md)에 승인된 시나리오·범위·승인 근거를 담아 별도 구현자에게 전달합니다. 사전 검토자에게 구현을 이어 맡기지 않습니다. 구현자는 통합 [코드베이스 설계](skills/codebase-design/SKILL.md)에 따라 구현·검증합니다.
5. 구현 결과를 받은 메인이 사전 검토자·구현자와 별도인 구현 리뷰 전용 서브에이전트를 생성합니다. [코드 리뷰](skills/code-review/SKILL.md)를 명시적으로 읽히고 [구현 리뷰 명세](skills/code-review/references/implementation-review-brief.md)로 승인된 범위, 기준 버전과 실제 변경, 관련 호출자, 검증 근거·미확인을 전달합니다.
6. 리뷰자는 실제 최종 diff·미추적 신규 파일·호출부를 읽기 전용으로 확인해 메인에만 반환합니다. 메인은 리뷰 중 쓰기 시점을 조정하며 의견의 근거와 채택 여부를 판단합니다. 같은 구현자에게 보완을 맡기고 같은 독립 리뷰자에게 최종 변경과 관련 영향을 재검토하게 합니다.
7. 메인은 실제 변경·검증 근거·독립 리뷰를 완료 기준에 대조해 최종 완료를 판단합니다. 리뷰 실패·미수행·검증 미확인을 통과로 간주하지 않습니다. 위임 기능이 없으면 제약과 남은 작업을 알립니다.

합의 밖의 계약 변경이나 중요한 영향은 해당 변경만 보류하고 같은 사전 검토자가 재검토한 뒤 메인이 사용자와 합의합니다. 독립적인 조사와 이미 승인된 작업은 계속할 수 있습니다. 승인 범위 안의 리뷰 보완은 재승인받지 않습니다.

최초 구현 요청만으로 아직 제시하지 않은 시나리오까지 승인됐다고 가정하지 않습니다. 이미 검토·승인한 구체 시나리오와 범위에 실질 변화가 없으면 검토와 승인을 반복하지 않습니다. 답변 없음이나 시간 경과는 승인이 아닙니다. 작은 변경은 짧게 검토하며 내부 함수명 등 승인 범위 안의 세부사항은 구현자가 정합니다.

전용 역할은 명세 기반 위임에 해당 스킬을 적용하는 방식입니다. 네이티브 에이전트 프로파일이나 OS 읽기 전용 환경을 자동 생성하지 않습니다. 사전 검토자와 구현 리뷰자는 코드·설정·문서·데이터 변경이나 커밋·푸시·설치 등 쓰기·외부 부수 효과를 수행하지 않습니다. 구현 리뷰자는 직접 수정·사용자 승인·완료 판단·재위임을 하지 않습니다. 커밋·푸시·Draft PR은 사용자 요청과 프로젝트 규칙이 허용한 범위에서 수행합니다.

## 번들 훅

[훅 설정](hooks/hooks.json)은 `UserPromptSubmit`에서 메인 워크플로우와 통합 `codebase-design` 본문, 모든 `SubagentStart`에서 같은 설계 본문을 전달합니다. `SessionStart`의 `compact|resume|fork`에서는 문맥을 이어갈 때 설계 본문을 다시 전달합니다. 역할 이름으로 주입 여부를 추측하지 않으며 수신자는 맡은 역할에 관련된 기준을 적용합니다.

[공통 로더](hooks/skill-context.cjs)는 엔트리포인트의 설치 위치에서 원본을 읽고 절대 원본 경로와 상대 링크 기준 폴더를 표시합니다. 시작 주입은 BOM·YAML frontmatter를 제외하고 stdin 종료를 기다리지 않습니다. 각 시작 훅의 `additionalContextLimit` 20000을 전체 결합 문맥에 대해 검사합니다. 문서 누락·빈 본문·한도 초과는 stderr와 실패 종료로 알리며 부분 문맥을 출력하거나 잘라내지 않습니다. 오류가 호스트의 모든 작업을 차단한다고 보장하지 않으며 `SubagentStart` 오류는 담당자 시작 차단 수단이 아닙니다.

번들에는 시작 지침 전달 훅만 등록합니다. 구현 후 리뷰는 메인이 별도 에이전트에 명세를 전달하는 필수 단계이며 종료 훅이나 별도 CLI 실행기를 사용하지 않습니다. `change-review`와 `code-review`의 전용 절차는 해당 담당자에게 명시적으로 읽힙니다.

시작 훅에는 PATH에서 실행할 수 있는 Node.js가 필요합니다. 등록 명령은 `process.env.PLUGIN_ROOT`로 설치 경로를 찾고, 원본 읽기는 실제 엔트리포인트 위치를 기준으로 합니다. Windows의 공백·한글 설치 경로를 지원합니다.

로컬 번들 변경만으로 현재 설치본 훅이 바뀌지는 않습니다. 설치본에 변경을 반영하고 `/hooks`에서 현재 정의를 검토·신뢰한 뒤 실제 이벤트를 확인해야 합니다. 지침 전달과 준수는 별개입니다. 메인은 실제 변경과 검증 근거를 통합 문서에 대조하고 독립 리뷰 이후의 수정도 확인합니다. 설치·활성화와 출력 형식은 [공식 훅 문서](https://learn.chatgpt.com/docs/hooks)를 따릅니다.

## 검증

```text
node --test hooks/*.test.cjs
```

테스트는 시작 이벤트만 등록되는 설정과 임시 설치 경로·별도 작업 디렉터리에서 원본 전체 전달, 문맥 복원, 경로 기준, 문맥 한도, 오류, 열린 stdin 동작 및 Windows 실행을 확인합니다. 실제 에이전트의 판단이나 호스트의 지침 준수까지 이 테스트만으로 검증하지 않습니다. 독립 리뷰의 생성·전달·보완·재검토는 실제 위임 결과와 최종 변경으로 확인합니다.
