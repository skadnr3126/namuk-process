# 남욱 프로세스

사용자 요청을 검증해 작업 맥락을 만들고 구현 담당자에게 명세를 전달한 뒤 실제 결과를 완료 기준과 대조하는 플러그인입니다.

## 작업 흐름

1. 메인이 [요청 검증과 구현 위임](skills/request-to-implementation/SKILL.md)에 따라 매 요청의 의도·대상·제약·완료 기준을 내부적으로 확인합니다.
2. 필요한 맥락을 조사합니다. 다음 행동을 결정할 정보가 부족할 때만 질문하고 이미 확보한 맥락은 재사용합니다.
3. 설명·분석은 메인이 직접 처리합니다. 구현은 [작업 명세](skills/request-to-implementation/references/task-brief.md)와 파일 소유권을 정해 서브에이전트에 위임합니다.
4. 구현 담당자는 시작할 때 프로젝트 feature map과 관련 wiki를 읽고 [코드베이스 설계](skills/codebase-design/SKILL.md)에 따라 실제 코드를 확인하고 설계·구현·자체 검증합니다.
5. 담당자는 검증 후 자기 기능 문서·wiki를 갱신합니다. 메인은 코드·문서와 검증 근거를 확인하고 공통 색인 변경을 취합한 뒤 완료를 판단합니다. 부족하면 같은 담당자에게 보완을 요청합니다.

사용자 요구, 확인한 사실, 가정과 미확인 사항을 구분합니다. 매 요청의 검증이 매번 질문하거나 모든 검증 스킬을 실행한다는 뜻은 아닙니다. 커밋·푸시·Draft PR은 사용자 요청과 프로젝트 규칙이 허용한 범위에서 수행합니다.

## 프로젝트 맥락의 읽기와 갱신

문서는 프로젝트 저장소에 두고 기존 경로를 유지합니다. 문서가 없다면 `docs/feature-map.md`를 공통 색인, `docs/features/<기능>.md`를 기능 문서, `docs/wiki/<주제>.md`를 설계 이유와 제약을 설명하는 wiki로 사용합니다. 메인은 위임 전에 이번 작업에 필요한 최소 색인을 만들고 읽을 문서와 갱신할 파일을 명세에 지정합니다. 전체 wiki를 미리 만들지 않습니다.

병렬 구현 담당자는 각각 소유한 기능 문서·wiki를 갱신하고 공통 색인의 추가·수정·삭제·이름 변경 제안을 반환합니다. 메인은 근거를 검토해 공통 색인을 취합합니다. 다음 구현 담당자는 그 색인에서 관련 문서·코드·검증 방법을 찾아 시작합니다. 읽기 조사·리뷰만 맡은 에이전트는 문서 오류를 반환하고 파일을 수정하지 않습니다.

## 번들 훅

[훅 설정](hooks/hooks.json)은 `UserPromptSubmit`에서 `request-to-implementation`, `SubagentStart`에서 `codebase-design`을 주입합니다. [주입 스크립트](hooks/inject-skill.cjs)가 설치된 플러그인의 스킬 원문을 읽으므로 훅에 판단 규칙을 복사하지 않습니다. 모든 서브에이전트 시작에 설계 스킬을 전달하고 실제 위임 역할에 따라 구현·문서 갱신 책임을 적용합니다. 문서 갱신은 에이전트의 완료 절차이며 종료 훅이 자동으로 파일을 수정하지 않습니다.

Node.js가 실행 환경의 PATH에 있어야 합니다. POSIX와 Windows 명령을 각각 제공합니다. 실행 위치와 플러그인 경로의 공백에 의존하지 않으며, 상대 문서 링크를 해석할 스킬 원본 경로도 전달합니다. `additionalContextLimit`은 원문이 기본 출력 한도로 잘리는 것을 줄이기 위해 20000으로 지정했습니다. 스킬이 커지면 이 한도를 다시 검토해야 합니다.

로컬 번들 구현과 스크립트 검증을 완료해도 현재 설치본에서 자동 주입이 활성화됐다는 뜻은 아닙니다. 설치본에 변경을 반영하고 `/hooks`에서 현재 정의를 검토·신뢰한 뒤 실제 이벤트 실행을 확인해야 합니다. 설치·활성화만으로 훅을 신뢰하지 않는 동작과 출력 형식은 [공식 훅 문서](https://learn.chatgpt.com/docs/hooks)를 따릅니다. 검증·독립 리뷰 훅은 포함하지 않았습니다.

로컬 검증은 저장소 루트에서 `node --test hooks/inject-skill.test.cjs`로 실행합니다. 실제 스크립트를 다른 작업 위치와 공백이 있는 설치 경로에서 실행하고, 두 이벤트의 원문 주입, 잘못된 입력, 누락된 스킬과 manifest 연결을 확인합니다.

상세 판단 기준은 [요청 검증](skills/verify-request/SKILL.md)에 모았습니다. 명확성, 실제 맥락과의 적합성, 목표와 수단의 연결을 필요한 범위에서 확인합니다.
