# 실행 흐름으로 설명하기

사용자가 구체적인 동작 하나의 결과를 예측할 수 있도록 설명한다. 버튼이나 입력에서 시작해 데이터가 사용되는 코드와 결과가 나타나는 곳까지 연결한다.

기본 설명 경로는 다음과 같다.

```text
버튼 또는 입력
→ 입력 데이터
→ 호출 경로
→ 실제 처리 코드
→ 메모리와 저장 데이터의 변화
→ 반환값
→ 화면 또는 호출자가 관찰하는 결과
```

실제 동작에 저장이나 화면이 없으면 해당 단계가 없음을 짧게 밝히고 실제 결과에서 끝낸다. 설명 틀에 맞추려고 존재하지 않는 처리를 추가하지 않는다.

## 질문에 맞는 시작점과 범위 정하기

- 사용자가 지목한 버튼, 함수, 명령 또는 표현식을 시작점으로 삼는다. 요청이 넓으면 대표 동작 하나를 골라 선택을 밝힌다.
- 버튼 동작을 묻는다면 클릭부터 결과 반영까지 설명한다. 함수 이름 목록이나 전체 구조 소개에서 끝내지 않는다.
- 작은 문법 질문은 해당 표현식, 현재 호출부, 관찰되는 효과까지 설명한다. 
- 이전 설명에서 확인한 경로는 재사용한다. 후속 질문에서는 연결이 빠졌던 부분과 그 앞뒤를 보충한다.
- 사용자의 질문이 멈췄거나 주제가 바뀐 것을 이해의 확정 증거로 삼지 않는다. 매번 확인 질문이나 퀴즈로 끝내지 않는다.

## 설명 전에 실제 경로 확인하기

시작점의 호출부와 실제 처리 코드를 읽는다. 콜백, 별칭, 공통 전달 함수 뒤에서 데이터를 소비하는 곳까지 찾는다.

- 함수 이름을 넘기는 코드와 그 함수를 실제로 호출하는 코드를 구별한다.
- 분기 조건, 대입문, 저장 호출, 응답 생성, 결과 소비 코드를 확인한다.
- 프로세스나 네트워크를 건너면 발신 코드와 수신 코드를 함께 확인한다.
- 관련 파일과 심볼을 근거로 설명한다. 사용할 수 있으면 파일의 실제 줄로 연결되는 링크를 붙인다.
- 소스로 확인한 동작, 직접 실행해 확인한 결과, 추정한 내용을 구별한다. 소스만 읽고 DB의 현재 행 수나 프로세스 상태를 확인했다고 말하지 않는다.
- 설명을 위해 운영 데이터 변경, 서비스 재시작, 코드 수정까지 수행하지 않는다. 추가 작업은 사용자 요청 범위에서 판단한다.

## 한 사례를 끝까지 연결하기

정상 사례를 먼저 설명한다. 아래 항목은 조사와 설명의 기준이며, 답변에 항상 같은 제목이나 분량을 강제하는 틀이 아니다.

### 1. 시작 시점과 입력값

어떤 버튼을 누르거나 어떤 값을 입력하는지 먼저 정한다. 결과를 바꾸는 초기 상태도 함께 밝힌다.

- 실제 데이터 구조를 짧은 객체나 필드 표로 보여준다. 값은 실제 확인값인지 설명용 예시인지 표시한다.
- 필드의 출처, 타입, 단위를 필요한 범위에서 설명한다. 입력 문자열과 변환된 숫자, 초와 밀리초, ID와 객체 전체를 구별한다.
- 새 객체가 만들어지는지, 기존 객체를 수정하는지, 기존 객체의 참조를 전달하는지 확인한다.

### 2. 호출과 데이터 전달

시작점부터 처리 지점까지 호출 순서를 보여준다. 각 단계에서 앞의 값이 다음 매개변수에 어떻게 들어가는지 연결한다.

- 콜백은 부모가 넘긴 실제 함수까지 연결한다. "부모에게 전달한다"에서 멈추지 않는다.
- `{ settings }` 같은 축약 표기는 혼동될 때 `{ settings: settings }`로 풀어 보여준다.
- 객체 전체를 다른 이름의 인자로 받는다면 내부 값이 그 객체에 남아 있음을 보여준다.
- 요청 포장, JSON 변환, 역직렬화, 명령 종류 변환이 있으면 전후 형태를 짧게 비교한다.
- 서로 다른 함수에 `next` 같은 이름이 반복되면 각각 무엇을 담는지 구별한다. 이름이 같다고 같은 객체로 설명하지 않는다.

### 3. 실제 소비 코드와 실행 조건

전달받은 값을 실제로 읽거나 사용하는 분기와 문장을 발췌한다. "엔진이 처리한다" 대신 어떤 조건에서 어떤 필드를 바꾸는지 설명한다.

- 클릭 즉시 실행하는 처리와 반복 작업이 나중에 실행하는 처리를 구별한다.
- 결과를 예측하는 데 필요한 실행 조건을 밝힌다. 허용 플래그, 가격 조건, 최신성 검사, 한도, 주기 작업이 해당할 수 있다.
- 조건이 충족되지 않으면 대기하는지, 오류를 반환하는지, 이번 처리를 건너뛰는지 설명한다.

### 4. 메모리와 저장 데이터 변화

무엇이 현재 상태의 기준인지 밝힌다. 임시 편집값, 화면이 받은 복사본, 서버 메모리, DB 데이터를 구별한다.

- 같은 사례의 전후 값을 보여준다. 예를 들어 배열에 새 항목을 추가하는지, 기존 항목의 상태만 바꾸는지 명시한다.
- 저장할 때 실제 저장 위치와 범위를 설명한다. 행 일부를 갱신하는지, 전체 JSON을 다시 저장하는지 확인한다.
- DB 저장과 메모리 갱신의 순서를 확인한다. 저장 실패 시 어떤 값이 유지되는지도 핵심 분기일 때 설명한다.
- 응답용 복사본과 계속 갱신되는 원본 상태를 구별한다.

### 5. 결과를 소비하는 코드와 보이는 변화

반환값을 받았다는 설명에서 끝내지 말고, 그 값을 사용하는 코드까지 연결한다.

- 화면 상태 대입, 재조회, 이벤트 수신 중 무엇이 결과를 반영하는지 보여준다.
- 목록, 문구, 수치, 버튼이 어떻게 달라지는지 해당 조건부 렌더링이나 결과 소비 코드와 연결한다.
- 후속 조회나 주기 작업을 기다려야 하면 즉시 반영되는 변화와 이후 변화를 구별한다.
- 화면이 없는 흐름은 파일 생성, 로그, 호출자 결과처럼 실제 관찰 가능한 결과로 끝낸다.

## 설명의 깊이와 표현 조절하기

새 개념이 흐름 이해를 막으면 그 자리에서 필요한 만큼 풀고 원래 흐름으로 돌아온다. 문법은 정의, 현재 코드에서의 의미, 작은 예시 순서로 설명한다. 외부 라이브러리의 내부 구현 전체까지 따라가지는 않는다.

코드 발췌와 짧은 전후 값으로 설명한다. 발췌에서 생략한 부분은 표시하고, 설명용으로 풀어 쓴 코드를 실제 소스 원문과 구별한다. 긴 한 줄은 줄바꿈한다. 필요하면 호출 순서도나 상태 변화 표를 추가하되 본문의 연결을 대신하지 않는다.

답변을 마치기 전에 같은 입력값이 처리 코드와 결과까지 이어졌는지 확인한다. 호출된 곳을 다시 "다른 곳에서 처리한다"로 남기지 않는다. 미확인 경로가 있으면 그 지점과 확인할 수 없었던 이유를 명시한다.
