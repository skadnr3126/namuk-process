# 판단기준스킬

- 통합 [코드베이스 설계](../codebase-design/SKILL.md)를 사용해 리뷰한다. 실제 변경과 관련 호출부에 대조한다. 변경과 보존 대상, 책임과 지식의 위치, 공개 계약과 외부 형식, 상태·오류의 의미, 호출자·데이터 이행과 검증 근거를 관련 범위에서 확인한다.

## 구현 후 독립 리뷰 담당자

메인이 구현 결과를 회수한 뒤 이 스킬을 명시적으로 읽도록 별도 리뷰 전용 서브에이전트를 생성한다. 같은 작업의 사전 변경 검토자·구현자와 다른 에이전트로 둔다. 일반 코드·diff·PR 리뷰에도 아래 판단 기준을 적용하되, 이 절의 전달·반환 절차는 메인이 위임한 구현 후 리뷰에 사용한다.

메인은 [구현 리뷰 명세](references/implementation-review-brief.md)에 목적, 승인된 시나리오와 범위, 완료 기준, 저장소·작업 트리·기준 버전, 실제 변경 범위와 기존 사용자 변경, 구현자의 검증 근거·미확인을 담는다. 메인은 리뷰 대상의 쓰기 담당과 시점을 조정해 리뷰 중 구현자가 대상 변경을 덮어쓰지 않게 한다. 기준이나 범위가 없어 결론을 낼 수 없으면 메인에 확인을 요청한다.

리뷰 담당자는 읽기 전용으로 실제 최종 diff, 미추적 신규 파일과 관련 호출부를 직접 읽는다. 구현자의 요약·완료 선언·테스트 존재를 검증 근거로 대신하지 않는다. 코드·설정·문서·데이터를 수정하거나 커밋·푸시하지 않는다. 쓰기나 외부 부수 효과를 일으킬 검증은 직접 실행하지 않고 필요한 확인으로 반환한다. 사용자 승인·최종 완료 판단·다른 에이전트 위임을 수행하지 않으며 결과는 메인에만 반환한다. 이 역할 지침이 OS의 읽기 전용 환경을 자동 생성한다고 가정하지 않는다.

검토한 버전과 실제 범위, 발견사항과 심각성, 문제를 일으키는 입력·상황, 근거 위치, 기대 동작과 실제 동작, 확인 방법과 검증 한계를 반환한다. 발견사항이 없다는 결론과 확인하지 못한 항목은 구분한다. 재검토에서는 이전 지적의 해결·미해결·미확인을 구분하고 수정된 최종 변경과 영향받는 호출부를 확인한다.

메인은 근거와 채택 여부를 판단해 같은 구현자에게 보완을 맡기고 같은 독립 리뷰자에게 최종 변경을 재검토하게 한다. 승인 범위 안의 보완은 재승인을 요구하지 않는다. 합의 밖 계약 변경이 필요한 의견은 메인에 반환해 사전 변경 검토와 사용자 합의 경로로 처리한다. 리뷰 실패·미수행·검증 미확인을 통과로 보고하지 않는다.

## 추가적인 기준들

- 너무 많은 기능을 한 번에 구현하여 향후 유지보수 비용이 증가하는 경우
- 특정 기술 스택이나 라이브러리에 의존하여 향후 변경이 어려워지는 경우
- 코드 구조가 복잡하여 새로운 기능 추가나 변경이 어려워지는 경우
- 설계가 유연하지 않아 미래의 요구사항에 대응하기 어려운 경우
- 하나의 파일이나 함수에 너무 많은 책임이 집중되어 있어 향후 변경이 어려워지는 경우


## 범위와 근거 확인

사용자가 지정한 diff, PR, 파일 또는 기능을 대상으로 삼는다. 변경 리뷰라면 기준 버전과 diff를 확인하고, 기존 코드 리뷰라면 지정한 기능의 호출 경로를 확인한다. 범위가 불명확해 결론이 달라질 때만 필요한 범위를 확인한다.

목적과 실제 사용 상황을 기존 요청·문서·코드에서 파악한다. 사용자에게 없는 목적이나 우선순위를 만들지 않는다. 변경 줄만 보지 말고 관련 호출부, 입력과 출력, 데이터 흐름, 상태 갱신, 오류 처리와 기존 검증을 필요한 만큼 읽는다. 변경에서 발견한 기존 문제는 이번 변경이 만든 문제와 구분하고 범위 밖 조사를 무제한으로 넓히지 않는다.

리뷰 요청 자체로 수정·커밋·배포 권한을 얻지 않는다. 읽기 조사와 허용된 검증으로 판단하며, 이미 별도로 받은 수정 권한은 그 범위 안에서 유지한다.
