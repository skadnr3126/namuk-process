# 구현 작업 명세

요청 검증과 구현 전 변경 검토를 마치고 사용자 합의·구현 승인을 확인한 뒤 구현을 위임할 때 사용한다. 작은 수정은 각 항목을 한두 문장으로 작성하고 해당하지 않는 항목은 생략한다. 사용자 요구와 메인의 해석·가정을 분리한다. 목적과 우선순위는 확인한 대화와 근거에서 가져오고, 빈 항목을 채우기 위해 만들지 않는다. 진행을 막는 미정 사항은 위임 전에 해소한다.

## 전달 형식

```text
작업 목적
- 누가 어떤 상황에서 겪는 문제를 왜 해결하려는지 적는다.

기대 결과와 기능
- 사용자가 경험할 변화와 각 기능이 그 변화에 어떻게 기여하는지 적는다.

승인된 변경 시나리오와 합의 근거
- 현재 흐름과 승인된 변경 후 흐름, 책임을 둘 위치를 적는다.
- 사용자가 합의한 결정과 구현 승인 발언·범위의 근거를 적는다.
- 허용한 계약 변경과 보존 대상, 영향받는 호출자·저장 데이터를 적는다.
- 합의 밖의 영향을 발견했을 때 재협의할 조건을 적는다.

완료 기준
- 기대 결과의 충족 여부를 관찰할 동작으로 적는다.
- 기준별 확인 방법을 적는다.

판단 우선순위와 제외 범위
- 요구가 충돌하거나 선택이 필요할 때 적용할 확정된 우선순위와 근거를 적는다.
- 이번 작업에서 제외하기로 한 범위를 적는다.

사용자 요구와 제약
- 사용자가 확정한 요구와 변경하면 안 되는 동작·계약·데이터를 적는다.
- 로컬 작업, 커밋, 푸시, PR 등 허용된 작업 범위를 적는다.

작업 범위와 파일 소유권
- 저장소와 작업 트리, 담당 파일 또는 모듈과 영향받는 호출자를 적는다.
- 다른 담당자의 소유 범위와 공유 작업의 관리자를 적는다.

확인한 사실과 근거
- 관련 코드·설정 위치와 확인한 현재 동작을 적는다.
- 적용할 프로젝트 지침과 검증 명령을 적는다.

가정과 미확인 사항
- 메인의 해석과 아직 조사하지 않은 사실을 구분한다.
- 담당자가 조사할 항목과 사용자 결정이 필요한 조건을 적는다.

구현과 검증
- 코드베이스 설계 스킬을 적용하고 실제 코드와 명세를 대조한다.
- 명세의 오류나 중요한 누락은 메인에 보고한다.
- 합의 밖 계약 변경이나 중요한 영향은 해당 변경만 보류하고 메인에 재검토를 요청한다. 승인 범위 안의 내부 구현 세부사항은 담당자가 판단한다.
- 완료 기준에 필요한 동작 검증과 프로젝트 필수 검사를 수행한다.
- 사용자와 다른 담당자의 변경을 보존한다.
- 메인이 별도 구현 리뷰자에게 전달할 수 있도록 기준 버전·실제 변경 범위·미추적 신규 파일과 검증 근거를 반환한다. 리뷰 중에는 메인이 정한 쓰기 시점을 지킨다.
- 메인이 전달한 리뷰 의견 중 승인 범위 안의 보완을 같은 명세에서 수행한다. 합의 밖 영향은 해당 변경을 보류해 보고하고, 보완 후 최종 변경 범위와 검증 결과를 반환한다.

반환 결과
- 변경과 보존 대상, 책임을 둔 위치와 영향받은 호출자
- 완료 기준별 충족·미충족·미확인 및 실제 검증 근거
- 미완료·미검증 항목과 필요한 사용자 결정
- 맡긴 제출 작업의 확인된 위치와 상태
```

## 결과를 해석하는 기준

명령 실행 여부와 검증한 동작을 구분한다. 소스 확인, 단위 테스트, 실제 앱이나 외부 시스템에서 관찰한 근거를 구분해 반환한다. 검증 실패는 원인과 보완 상태를 적고, 검증 불가는 실행 조건과 남은 확인을 적는다. 메인은 별도 구현 리뷰자의 의견과 이 결과를 완료 기준에 대조해 같은 구현자에게 보완을 요청하고 같은 리뷰자에게 최종 변경을 재검토하게 한다.
