# 구현 작업 명세

요청 검증을 마치고 구현을 위임할 때 사용한다. 항목의 양은 작업 규모에 맞춘다. 사용자 요구와 메인의 가정을 분리하고 진행을 막는 미정 사항은 위임 전에 해소한다.

## 전달 형식

```text
목표와 완료 기준
- 사용자가 원하는 결과와 관찰할 동작을 적는다.
- 기준별 확인 방법을 적는다.

사용자 요구와 제약
- 사용자가 확정한 요구와 변경하면 안 되는 동작을 적는다.
- 로컬 작업, 커밋, 푸시, PR 등 허용된 작업 범위를 적는다.

작업 범위와 파일 소유권
- 저장소와 작업 트리, 담당 파일 또는 모듈을 적는다.
- 다른 담당자의 소유 범위와 공유 작업의 관리자를 적는다.

확인한 사실과 근거
- 관련 코드·설정 위치와 확인한 현재 동작을 적는다.
- 적용할 프로젝트 지침과 검증 명령을 적는다.

가정과 미확인 사항
- 메인의 해석과 아직 조사하지 않은 사실을 구분한다.
- 담당자가 조사할 항목과 사용자 결정이 필요한 조건을 적는다.

구현과 검증
- 코드베이스 설계 스킬을 적용하고 실제 코드와 명세를 대조한다.
- 명세의 오류나 중요한 누락은 메인에 보고한다.
- 완료 기준에 필요한 동작 검증과 프로젝트 필수 검사를 수행한다.
- 사용자와 다른 담당자의 변경을 보존한다.

반환 결과
- 변경 요약과 파일 위치
- 완료 기준별 충족·미충족·미확인 및 실제 검증 근거
- 미완료·미검증 항목과 필요한 사용자 결정
- 맡긴 제출 작업의 확인된 위치와 상태
```

## 결과를 해석하는 기준

명령 실행 여부와 검증한 동작을 구분한다. 소스 확인, 단위 테스트, 실제 앱이나 외부 시스템에서 관찰한 근거를 구분해 반환한다. 검증 실패는 원인과 보완 상태를 적고, 검증 불가는 실행 조건과 남은 확인을 적는다. 메인은 이 결과를 원래 완료 기준에 대조하고 필요한 보완을 같은 담당자에게 요청한다.
