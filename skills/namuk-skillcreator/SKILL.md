# 새 스킬 설계와 생성

반복할 판단과 작업 방법을 작은 책임의 스킬로 만든다. 기존 스킬 수정은 새 스킬 분리에 필요한 경계 조정으로 제한한다.

## 생성 필요성 판단

1. `.codex-plugin/plugin.json`, [플러그인 철학](../../플러그인철학.md), [스킬 기능과 책임](../../skill-refer.md), 관련 스킬과 참조를 읽는다. 스킬 기능과 책임 문서에 지정된 로컬 원본에서 스킬 생성과 관련 변경을 수행한다. [공통 변경 절차](../../skill-refer.md#공통-변경-절차)에 따라 수정 전에 고정 `change` 브랜치를 준비한다. 위임된 같은 작업의 `change`는 재사용하고 기준 커밋·요청 당시 작업폴더를 유지한다. 기존 사용자 변경을 보존하며 설치 캐시를 수정하지 않는다.
2. 입력에서 반복 문제, 생성 이유, 기대 결과, 범위와 사용자 제한을 확인한다. 이유가 없으면 현재 맥락에서 새 스킬이 최선인지 검토한다. 이미 답이 있는 질문은 반복하지 않는다.
3. 기존 수정이나 참조 연결로 충분하면 생성하지 않고 이유와 대안을 호출자에게 반환한다. 독립 호출에서 기존 수정이 필요하면 [회고와 개선](../reflect/SKILL.md)으로 연결한다. 생성 이유가 있어도 기능이 겹치는 스킬은 복제하지 않는다.

## 작은 책임으로 작성

- 한 가지 알아볼 수 있는 목적과 소유 책임을 정한다. 독립적으로 호출할 이유가 없는 단계를 별도 스킬로 나누지 않는다.
- 사용 시점과 비발동 상황, 입력과 권한, 직접 수행할 범위, 다른 담당자에게 넘길 내용과 반환 결과, 실패·검증 불가 시 중단 지점을 적는다.
- 독립 평가, 병렬 조사, 분리 가능한 작업에 서브에이전트가 유용한지 판단한다. 스킬 호출과 새 에이전트 생성을 구분하고 짧은 순차 작업에는 담당자를 불필요하게 늘리지 않는다. 위임 시 소유 파일·작업 트리를 정하고 다른 작업자의 변경을 보존하도록 전달한다.
- 이름은 소문자 단어를 하이픈으로 연결한 형식으로 정하고 폴더명과 문서 머리말 `name`을 일치시킨다. `description`에는 사용 시점과 제외 범위를 적는다.
- 기본 절차는 `SKILL.md`에 둔다. 선택적으로 읽을 자료가 실제로 필요할 때만 `references/`를 추가하고 읽을 시점을 연결한다. 시스템 일반론, 중복 절차, 미래를 위한 빈 구조를 추가하지 않는다.
- 기존 담당자가 있는 검증·제출 절차를 재구현하지 않는다. 관련 스킬의 연결이 순환하지 않는지 확인한다. 사용자 제한과 기존의 무관한 지침을 보존한다.

## 갱신·검증·반환

생성 담당자는 스킬 기능과 책임 문서에 목적·기능·사용 시점·제외 범위·입출력과 연결 관계를 갱신한다. 등록 정보, 야믈 형식의 문서 머리말, 이름·폴더 일치, 설명 길이, 참조 경로와 변경 내역을 확인하고 사용 가능한 검사기 및 `git diff --check`를 실행한다.

이번 변경만 `change`에 커밋해 기준본·변경본 커밋을 고정한다. 새 스킬은 새 동작을 추가하므로 요청 당시 작업폴더와 함께 [플러그인 개선 검증](../verify-improvement/SKILL.md)에 독립 비교를 맡긴다. 기존본에 해당 스킬이 없어도 같은 사용자 요청을 수행시켜 비교한다. 기존 내용을 고칠 때 의미와 동작이 그대로인 표현 수정은 기본 검사로 마친다. 검증 담당자는 판정과 근거만 반환한다. 형식 검사를 행동 검증이라고 부르지 않는다.

회고와 개선에서 위임받았다면 생성 이유, 변경 파일, 기능 문서 갱신, 검증 결과와 한계를 반환한다. 직접 호출됐다면 생성 담당자가 공통 변경 절차의 판정별 제출·폐기·보존을 관리한다. 개선 판정이고 제출 범위인 경우 [플러그인 변경 제출](../submit-improvement/SKILL.md)에 제출을 위임하고 결과를 회수한다. 로컬 생성·검증만 요청된 작업은 제출하지 않는다.
