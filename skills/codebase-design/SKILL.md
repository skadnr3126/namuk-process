# 코드베이스 설계

필요한 부분을 독립적으로 바꾸고, 보존해야 할 데이터와 동작을 지킬 수 있게 설계한다. 코드 구현·수정·리팩터링·설계·리뷰에 이 문서를 적용한다. 작은 변경은 관련 위치와 영향만 짧게 판단한다. 문서를 적용하기 위해 불필요한 계층·파일·인터페이스·보고서를 추가하지 않는다. 프로젝트 규모와 미래 요구는 확인한 근거에서 가져온다.

메인은 이 기준으로 설계·작업 명세·완료 근거를 판단하고 사용자 요청 검증과 범위를 유지한다. 구현 담당자는 명세를 실제 코드와 대조하고 설계·구현·검증한다. 명세의 오류나 중요한 누락은 메인에 보고한다. 조사·설명·리뷰 담당자는 맡은 산출물에 기준을 적용하며 구현 권한을 가정하지 않는다. 이 문서는 요청 검증이나 위임 순서를 새로 정하지 않는다.

## 변경할 것과 보존할 것을 먼저 정한다

실제 호출부와 데이터 흐름을 읽고 구체적으로 무엇을 바꾸는지 확인한다. 표시 이름, 외부 응답, 조회 정책 변경처럼 변경 이유를 설명한다. 유지할 입력·결과·오류·사용 조건·저장 데이터와 영향받는 호출자를 확인한다. 내부 구현 교체와 공개 계약 변경을 구분한다.

작은 수정은 관련 코드 확인으로 충분하다. 책임이 얽히거나 데이터와 외부 부수 효과가 걸린 변경은 소유 모듈, 함께 바뀔 규칙, 보존 대상과 검증 방법을 명세나 짧은 메모로 연결한다. 확인한 사실, 가정, 사용자 결정이 필요한 사항을 구분하며 요청 범위를 확대하지 않는다.

## 책임은 변경 이유와 지식의 소유권으로 정한다

모듈은 공개 계약과 내부 구현을 가진 기능이다. 함수·클래스·패키지 등 크기를 한정하지 않는다. 어떤 요구 때문에 바뀌며 어떤 규칙과 상태를 소유하는지로 책임을 판단한다. 정보를 사용하는 곳과 의미를 결정하는 곳을 구분한다.

- 함께 바뀌는 지식은 담당 모듈에 모으고 같은 정의를 참조한다. 여러 호출부에서 공급자 응답이나 상태 규칙을 각각 해석하지 않는다.
- 이름이나 모양이 비슷하거나 여러 곳에서 쓴다는 이유만으로 공통화하지 않는다. 공통화는 함께 유지해야 할 의미와 규칙이 있을 때 한다. 현재 구현 수만으로 공통 의미를 배제하지 않는다.
- 같은 프로세스의 순수 계산이라도 독립적으로 바뀌는 정책은 구분한다. 함께 읽어야 이해되는 작은 코드는 함께 둔다. 줄 수와 파일 수를 목표로 나누거나 합치지 않는다.
- 폴더와 공개 입구에서 공개 타입·기능과 내부 구현을 구별할 수 있게 한다. 실제 의존관계도 그 책임을 따라야 한다.
- IPC·HTTP·CLI 등의 연결 코드는 입력을 받아 담당 모듈을 선택하고 결과를 전달한다. 공급자 정책과 외부 응답 해석은 소유 모듈에 둔다. 중간 계층을 유지하려면 그 계층이 소유하는 규칙이나 상태를 설명할 수 있어야 한다.

## 공통 계약, 전용 공개 계약, 외부 형식을 구분한다

인터페이스는 호출자가 모듈을 올바르게 사용하기 위해 알아야 할 계약 전체다. 타입과 함수뿐 아니라 불변조건, 호출 순서, 설정, 오류, 만료, 재시도, 성능 조건을 포함한다.

| 구분 | 담는 내용 | 소유 책임 |
|---|---|---|
| 공통 계약 | 여러 구현이 함께 사용하는 의미와 규칙 | 해당 계약을 사용하는 모듈들의 합의 |
| 전용 공개 계약 | 특정 구현의 기능을 호출하는 데 필요한 추가 입력과 결과 | 해당 구현 모듈 |
| 외부 형식 | 외부 필드명·응답·인증·서명·공급자 상태 | 연동 내부 구현 |

예를 들어 공급자 전용 수취인 정보는 화면이 입력해야 하므로 전용 공개 계약이다. 응답 성공 판정에만 쓰는 원시 필드는 연동 내부에서 해석한다. 공통 계약이 전용 공개 타입을 묶을 수는 있지만 인증 클라이언트나 비공개 외부 타입까지 참조하지 않는다.

신뢰 수준이 바뀌는 네트워크·저장소·프로세스 입력은 담당 경계에서 검증하고 내부 모델로 변환한다. 공통 화면과 계산이 외부 응답 형식을 직접 해석하지 않게 한다. 변환할 때 수량의 정밀도·단위, 태그, 조회 시점, 상태와 부분 성공 등 판단에 필요한 의미를 보존한다.

실제 차이는 구분 가능한 종류와 그 종류에 필요한 데이터로 표현한다. 무관한 선택 필드를 한 구조에 모아 빈 값으로 채우게 하지 않는다. 정보 없음과 미지원도 구분한다. 전용 공개 데이터가 없는 구현에 대칭적인 빈 파일을 만들 필요는 없다. 실제 등록 목록이 확장 지점이면 기준 ID에서 타입을 유도하거나 시작 시 연결 누락을 검사한다.

## 깊은 모듈은 호출자가 배울 맥락을 줄인다

깊이는 적은 인터페이스 지식으로 필요한 동작을 사용할 수 있는 정도다. 구현 줄 수, 메서드 수나 매개변수 수로 측정하지 않는다. 진입점 하나에 모드·플래그·숨은 조건을 몰면 더 복잡해질 수 있다.

호출자는 필요한 입력·결과·오류·사용 조건을 알고 기능을 사용할 수 있어야 한다. 인증 구성, 내부 요청 순서와 응답 해석은 담당 구현에 감춘다. 호출자가 실제로 지켜야 할 검토 선행, 만료, 중복 실행과 재시도 조건은 계약에 드러낸다.

깊은 모듈 내부에서도 독립적인 책임은 나눌 수 있다. 상태와 무효화 규칙도 그 책임과 함께 이동한다. 단순 전달 계층이나 범용 추상화를 추가하기 전에 호출자의 지식과 반복이 실제로 줄어드는지 확인한다. 검증 경로나 외부 격리가 필요할 때 의존성을 대체할 수 있게 하되 모든 의존성에 주입 구조를 만들지 않는다.

## 데이터와 상태의 생명주기를 소유한다

원본 데이터, 계산값, 캐시, 입력 초안, 검토 후 확정된 요청, 실행 결과를 구분한다. 하나의 사실을 여러 곳에서 독립적으로 갱신하지 않는다. 생성·검증·변경 담당과 읽기 담당을 확인한다. 파생값은 우선 계산으로 표현한다.

입력 변경 시 검토를 무효화하는 규칙은 관련 상태와 함께 소유한다. 실행 뒤 입력을 편집해도 이전 결과와 후속 내역 조회는 실제 실행했던 요청을 가리켜야 한다. 조회 담당의 로딩·성공·실패 전이와 외부 조회 구현은 기존 구조에 맞게 구분한다.

규칙 공유와 상태 공유는 별개다. 만료·일회성 소비 규칙은 공유해도 실제 티켓과 인증 상태는 구현 인스턴스가 각각 소유할 수 있다. 다른 인스턴스의 요청을 잘못 실행하지 않게 한다.

캐시가 필요한 경우 키·조회 조건·만료·새로고침·무효화·페이지 일관성의 담당을 정한다. 늦은 이전 응답이 최신 상태를 덮지 않게 최신성 판정, 취소와 중복 실행 정책을 관련 책임에 둔다. 변경 요청 전에 지운 캐시가 요청 도중 재생성될 수 있으므로 실행 전후와 열린 화면까지 고려한다. 로컬 캐시 갱신 실패가 이미 일어난 외부 실행 결과를 덮어쓰지 않게 한다.

## 오류 계약은 처리 여부의 불확실성을 보존한다

오류를 빈 성공이나 무조건 재시도 가능한 실패로 바꾸지 않는다. 검증 단계의 미전송, 외부 서비스의 명시적 거절, 처리됐을 수 있으나 응답을 확인하지 못한 상태를 구분한다. 계층을 거치거나 구조화된 응답을 읽지 못해도 부수 효과의 접수 여부가 불확실하다는 의미를 유지한다.

읽기 실패와 외부 부수 효과 실행 실패는 성격에 맞게 처리한다. 전체 실패·부분 성공·접수·처리 완료를 호출자가 필요한 수준으로 구분한다. 복구 안내에는 실제 요청 종류와 실행 내용을 사용한다. 출금은 출금 내역 확인, 주소 생성은 주소 재조회처럼 중복 실행을 피할 다음 행동을 제공한다.

## 교체와 계약 변경을 구분한다

교체 지점은 해당 코드를 고치지 않고 구현을 바꿔 연결할 수 있는 위치다. 어댑터는 그 자리의 계약을 만족하는 구현체다. 실제로 교체할 가치가 있거나 외부 의존성을 격리해야 할 때 둔다. 어댑터 개수로 필요성을 판단하거나 미래 공급자를 추측해 구조를 만들지 않는다. 내부 검증용 교체 지점을 모두 공개할 필요도 없다.

계약을 유지한 내부 교체는 기존 구현과 새 구현에 같은 계약 검증을 적용한다. 공개 계약 변경은 이유를 밝히고 실제 호출자·응답 검증·상태 전달까지 함께 이행한다. 관련 없는 구현의 수정을 줄이는 것이 국소성이며 필요한 호출자 변경까지 없애는 뜻은 아니다.

함께 바꿀 수 있는 내부 호출자는 같은 변경에서 이행하고 불필요한 옛 경로를 정리한다. 별도 배포되는 호출자와 기존 저장 데이터가 있으면 호환성 정책·마이그레이션·배포 순서를 정한다. 보존할 데이터와 진행 중 요청·부수 효과를 버려도 된다고 가정하지 않는다.

## 실제 계약과 관찰 가능한 결과로 검증한다

변경한 책임과 보존 대상에 맞는 검증을 선택한다. 기존 검사를 활용하고 필요한 검증을 보완한다. 정상 결과 외에 관련된 잘못된 입력·추가 필드, 변환과 정밀도, 부분 성공·불확실성, 만료·중복 실행, 늦은 응답, 조회 조건 변경, 호출자·저장 데이터 호환성을 확인한다. 관련 없는 항목을 모든 작업에 강제하지 않는다.

선언한 타입이나 제약만 믿지 말고 실제 요청을 받아들이는 역직렬화·IPC·HTTP·CLI 경로에서 조건을 확인한다. 화면 자동 입력은 실제 입력값을, 반복 조회 개선은 페이지 이동 시 외부 호출 횟수를 확인하는 등 사용자에게 보이는 결과와 실행 값을 대조한다. 모의 대체물의 통과를 실제 외부 연동의 검증으로 보고하지 않는다.

새 인터페이스 테스트가 생겼다는 이유만으로 기존 테스트를 삭제하지 않는다. 기존 테스트의 보장 동작이 새 검증에 포함됐는지 확인하고 중복·구현 결합 여부로 판단한다. 내부 계산의 중요한 불변조건을 정밀하게 검증할 이유가 있으면 유지한다.

완료 전 실제 변경과 관련 호출부를 읽고 책임·공개 계약·상태 소유권이 코드와 검증에서 일치하는지 확인한다. 결과에는 변경과 보존 대상, 책임을 둔 위치, 영향받은 호출자와 실제 검증 근거를 작업 규모에 맞게 담는다. 실행하지 못한 항목은 이유와 남은 확인으로 구분한다. 빌드 성공이나 적용 선언만으로 동작 검증을 대신하지 않는다.
