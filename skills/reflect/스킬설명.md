# Reflect 스킬 설명

## 목적

Reflect는 개발 과정에서 드러난 나의 암묵지를 구조화하고, 플러그인에 반영하는 과정을 돕기 위한 스킬이다. 매번 직접 스킬을 정리하고 관리하는 부담을 줄이고, 나는 개선 방향과 검증 결과를 확인하는 데 집중하고자 한다.

이 문서는 Reflect가 지향하는 동작과 흐름을 설명한다. 그 바탕은 [플러그인 철학](../../플러그인철학.md)에 있다.

## 사용 시점과 범위

플러그인을 사용하면서 더 나은 작업 방식을 발견하거나, 기존 내용을 바꿀 필요가 생겼을 때 사용한다. 작업 순서, 판단 기준, 검증 방법처럼 AI에게 전달할 수 있는 개발 지식과 작업 방식이 대상이다.

변경에는 기존 내용의 수정과 삭제, 새로운 내용이나 스킬의 추가가 포함된다. 사용자가 직접 반영할 항목을 지정할 수도 있고, AI가 현재 작업의 대화에서 개선 후보를 찾아 제안할 수도 있다.

## 반영 흐름

메인 에이전트는 개선 신호와 관련 대화·사용자 의도를 서브에이전트 하나에 전달하고 독립적인 사용자 작업을 계속한다. 담당 서브에이전트는 별도 worktree에서 수정·검증한 뒤 같은 맥락으로 submit-improvement를 실행해 PR을 제출한다. 제출만을 위한 에이전트를 추가로 만들지 않는다. 완료하면 PR 링크와 검증 결과를 메인에 반환한다. 준비된 일반 변경을 제출할 때는 submit-improvement만 서브에이전트에 맡길 수 있다.

### 1. 개선 후보 정리

어떤 작업공간에서 플러그인을 사용하든, 반영할 내용을 로컬 플러그인 저장소의 변경 후보로 정리한다. 무엇을 왜 바꾸려는지, 어느 내용을 추가·수정·삭제할지 설명한다.

### 2. 개선 근거 확인

현재 대화의 사용자 피드백과 관찰 결과를 근거로 반영할 항목을 고른다. 채팅에서 수정안 승인을 기다리지 않고 변경과 검증을 진행한다. 사용자는 PR에서 맥락과 검증 결과를 확인한다.

### 3. 별도 브랜치에서 변경

로컬 플러그인 저장소 `D:\Plugin\namuk-process`가 `skadnr3126/namuk-process`의 소스인지 확인하고, 별도 브랜치에 변경사항을 작성한다. 실행 지침은 [SKILL.md](SKILL.md)에 있다. 이 저장소가 검증과 PR의 기준이 된다.

### 4. 변경의 영향에 맞게 검증

오타나 문장 수정은 수정한 내용과 문맥을 확인한다. 스킬 생성·삭제나 동작에 영향을 주는 변경은 해당 영향을 확인할 수 있는 테스트를 수행한다.

큰 변경은 별도 워크트리에서 변경 전후를 비교한다. 변경 전에는 기존 플러그인으로 작업을 수행한다. 변경 후에는 테스트 환경에서 기존 플러그인을 비활성화하고, 수정한 로컬 플러그인을 주입해 같은 조건의 작업을 수행한다. 두 버전의 지침이 동시에 적용되지 않게 한다.

비교 결과를 바탕으로 변경이 의도한 개선을 만들었는지 판단한다.

### 5. PR로 최종 확인

`reflect-review` 브랜치(base)를 대상으로 변경 브랜치(head)에서 draft PR을 만든다. 변경 브랜치는 `reflect/<주제>-<고유값>`으로 만들며, 두 브랜치는 서로 달라야 한다. 발견 당시 맥락, 개선 근거, 변경 이유, 검증 방법과 실제 결과, 미확인 항목을 PR에 적는다. 사용자가 변경 내용과 검증 결과를 최종 확인한 뒤 병합한다.

### 6. 연결된 플러그인 업데이트

병합 후 사용자가 업데이트를 요청하면 Codex에 연결된 플러그인을 최신화한다. 업데이트에는 플러그인 마켓플레이스의 업그레이드 기능을 사용하며, 구체적인 명령과 적용 방식은 구현 시 확인한다.

이 흐름을 반복해 나의 작업 방식과 판단 기준을 플러그인에 반영하고, 검증한 내용을 다음 작업에서 사용한다.
