# Reflect 스킬 설명

## 목적

Reflect는 개발 과정에서 드러난 나의 암묵지를 구조화하고, 플러그인에 반영하는 과정을 돕기 위한 스킬이다. 매번 직접 스킬을 정리하고 관리하는 부담을 줄이고, 나는 개선 방향과 검증 결과를 확인하는 데 집중하고자 한다.

이 문서는 Reflect가 지향하는 동작과 흐름을 설명한다. 그 바탕은 [플러그인 철학](../../플러그인철학.md)에 있다.

## 사용 시점과 범위

플러그인을 사용하면서 더 나은 작업 방식을 발견하거나, 기존 내용을 바꿀 필요가 생겼을 때 사용한다. 작업 순서, 판단 기준, 검증 방법처럼 AI에게 전달할 수 있는 개발 지식과 작업 방식이 대상이다.

변경에는 기존 내용의 수정과 삭제, 새로운 내용이나 스킬의 추가가 포함된다. 사용자가 직접 반영할 항목을 지정할 수도 있고, AI가 현재 작업의 대화에서 개선 후보를 찾아 제안할 수도 있다.

## 반영 흐름

### 1. 개선 후보 정리

어떤 작업공간에서 플러그인을 사용하든, 반영할 내용을 로컬 플러그인 저장소의 변경 후보로 정리한다. 무엇을 왜 바꾸려는지, 어느 내용을 추가·수정·삭제할지 설명한다.

### 2. 변경 방향 승인

사용자가 개선 후보를 확인하고 반영할 항목을 승인한다. 승인한 항목을 기준으로 변경과 검증을 진행한다.

### 3. 별도 브랜치에서 변경

로컬 플러그인 저장소의 경로를 확인하고, 별도 브랜치에 변경사항을 작성한다. 이 저장소가 검증과 PR의 기준이 된다.

### 4. 변경의 영향에 맞게 검증

오타나 문장 수정은 수정한 내용과 문맥을 확인한다. 스킬 생성·삭제나 동작에 영향을 주는 변경은 해당 영향을 확인할 수 있는 테스트를 수행한다.

큰 변경은 별도 워크트리에서 변경 전후를 비교한다. 변경 전에는 기존 플러그인으로 작업을 수행한다. 변경 후에는 테스트 환경에서 기존 플러그인을 비활성화하고, 수정한 로컬 플러그인을 주입해 같은 조건의 작업을 수행한다. 두 버전의 지침이 동시에 적용되지 않게 한다.

비교 결과를 바탕으로 변경이 의도한 개선을 만들었는지 판단한다.

### 5. PR로 최종 확인

검증 결과가 적절하면 로컬 플러그인 저장소의 `main` 브랜치를 대상으로 PR을 만든다. 사용자가 변경 내용과 검증 결과를 최종 확인한 뒤 병합한다.

### 6. 연결된 플러그인 업데이트

병합 후 Codex에 연결된 플러그인을 최신화한다. 업데이트에는 플러그인 마켓플레이스의 업그레이드 기능을 사용하며, 구체적인 명령과 적용 방식은 구현 시 확인한다.

이 흐름을 반복해 나의 작업 방식과 판단 기준을 플러그인에 반영하고, 검증한 내용을 다음 작업에서 사용한다.
