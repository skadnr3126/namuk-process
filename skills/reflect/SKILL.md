# 회고와 개선

경험을 플러그인 개선으로 반영하고 필요한 후속 작업까지 관리한다. 사용자 발언, 인공지능의 행동, 실제 결과를 구분한다. 추측을 성공 사례로 기록하거나 일회성 요구를 보편적 규칙으로 만들지 않는다. 구체적인 개선 근거가 없으면 변경하지 않는다.

## 담당과 소스

메인은 사용자 요청과 제한, 관련 대화·관찰, 소스와 변경 범위를 서브에이전트 하나에 전달한다. 이미 개선 담당자로 위임받았다면 회고와 개선을 다시 위임하지 않는다. 같은 개선의 담당자가 있으면 재사용한다. 서브에이전트를 사용할 수 없으면 제한을 알리고 메인이 담당한다.

수정 대상은 [스킬 기능과 책임 문서의 로컬 원본](../../skill-refer.md#로컬-원본에서-변경-검토-요청까지)이다. 원본에 먼저 변경을 반영하고 같은 저장소에서 변경 검토 요청 제출로 이어간다. 깃 루트와 등록 정보의 이름이 `namuk-process`이고 `origin`이 `skadnr3126/namuk-process`인지 확인한다. 설치 캐시는 편집하지 않는다. 원본이 없거나 신원이 다르면 임의의 저장소로 대체하지 않는다.

담당자는 변경 파일과 작업 경로를 소유한다. 다른 작업자도 저장소를 사용하므로 타인의 변경을 되돌리지 않는다. 메인은 위임한 파일을 동시에 수정하지 않는다. 간접적으로 발견한 개선은 진행 중인 사용자 작업의 자연스러운 마무리 지점에서 처리한다. 자신의 제안을 새 근거로 삼아 재귀 실행하지 않는다.

## 개선 선택과 변경

1. [스킬 기능과 책임](../../skill-refer.md), 플러그인 철학, 관련 스킬과 참조를 읽고 수정·삭제·추가 중 필요한 작업을 판단한다.
2. [공통 변경 절차](../../skill-refer.md#공통-변경-절차)에 따라 수정 전에 원본의 고정 `change` 브랜치를 생성하거나 같은 작업의 브랜치를 재사용한다. 기준 커밋과 요청 당시 작업폴더를 기록하고 사용자 변경을 보존한다. 브랜치 준비를 제출 시점으로 미루지 않는다.
3. 기존 지침의 수정·삭제는 직접 수행한다. 규칙은 소유한 스킬에서 관리하고 다른 스킬은 참조한다. 변경한 기능과 책임을 스킬 기능과 책임 문서에도 갱신한다.
4. 새 스킬이 필요하면 반복 문제, 기존 스킬 수정으로 해결하기 어려운 이유, 기대 결과와 범위를 [새 스킬 설계와 생성](../namuk-skillcreator/SKILL.md)에 위임한다. 생성 담당자가 필요성을 재검토하도록 세부 설계를 미리 고정하지 않는다. 생성 담당자는 기능 문서 갱신과 검증 결과까지 반환한다.

## 검증 결과와 후속 작업

작성 담당자는 [기본 검사와 비교 요청 조건](../../skill-refer.md#검증-수준과-역할-분리)에 따라 기본 검사 후 이번 변경만 `change`에 커밋한다. 사용자 요청이 있을 때만 기준본·변경본 커밋, 요청 당시 작업폴더, 같은 요청·입력·관찰 기준을 [플러그인 개선 검증](../verify-improvement/SKILL.md)에 전달한다. 같은 커밋에 대해 생성 담당자가 받은 유효한 검사·비교 기록은 재사용한다.

후속 작업은 [공통 변경 절차](../../skill-refer.md#공통-변경-절차)를 따른다. 비교 미요청으로 기본 검사만 수행한 경우 또는 요청된 비교에서 개선이면 [플러그인 변경 제출](../submit-improvement/SKILL.md)을 실행할 별도 서브에이전트에 원본 경로, 기준·변경 커밋, 변경 파일, 개선 근거, 기본 검사 기록·비교 수행 상태·한계와 사용자 제한을 전달한다. 제출 중 원본을 동시에 수정하지 않는다. 변경 검토 요청 제출 성공 후에는 로컬 `change`를 보존한 채 `main`으로 복귀한다. 요청된 비교의 회귀·차이 없음이면 근거를 보존하고 다른 미제출 작업이 없을 때만 `change`를 삭제한다. 다른 작업이 있거나 구분이 불확실하면 브랜치를 보존한다. 판단 불가·실패면 `change`를 보존한다. 사용자 범위 제한은 우선하며 별도 수정안 승인 단계는 두지 않는다.

결과를 회수해 변경 요약, 기본 검사·비교 수행 상태와 한계, 확인된 변경 검토 요청 주소, 원본의 현재 브랜치와 로컬 `change` 정리 여부를 반환한다. 비교 미실행 변경을 검증된 개선으로 보고하지 않는다. 원본 작업 트리와 열린 변경 검토 요청의 원격 변경 브랜치는 유지한다.
