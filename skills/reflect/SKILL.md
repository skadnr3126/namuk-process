# Reflect

경험을 플러그인 개선으로 반영하고 필요한 후속 작업까지 관리한다. 사용자 발언, AI의 행동, 실제 결과를 구분한다. 추측을 성공 사례로 기록하거나 일회성 요구를 보편적 규칙으로 만들지 않는다. 구체적인 개선 근거가 없으면 변경하지 않는다.

## 담당과 소스

메인은 사용자 요청과 제한, 관련 대화·관찰, 소스와 변경 범위를 서브에이전트 하나에 전달한다. 이미 개선 담당자로 위임받았다면 reflect를 다시 위임하지 않는다. 같은 개선의 담당자가 있으면 재사용한다. 서브에이전트를 사용할 수 없으면 제한을 알리고 메인이 담당한다.

수정 대상은 [skill-refer.md의 로컬 원본](../../skill-refer.md#로컬-원본에서-pr까지)이다. 원본에 먼저 변경을 반영하고 같은 저장소에서 PR 제출로 이어간다. Git 루트와 manifest의 이름이 `namuk-process`이고 origin이 `skadnr3126/namuk-process`인지 확인한다. 설치 캐시는 편집하지 않는다. 원본이 없거나 신원이 다르면 임의의 저장소로 대체하지 않는다.

담당자는 변경 파일과 작업 경로를 소유한다. 다른 작업자도 저장소를 사용하므로 타인의 변경을 되돌리지 않는다. 메인은 위임한 파일을 동시에 수정하지 않는다. 간접적으로 발견한 개선은 진행 중인 사용자 작업의 자연스러운 마무리 지점에서 처리한다. 자신의 제안을 새 근거로 삼아 재귀 실행하지 않는다.

## 개선 선택과 변경

1. [skill-refer.md](../../skill-refer.md), 플러그인 철학, 관련 스킬과 참조를 읽고 수정·삭제·추가 중 필요한 작업을 판단한다.
2. 로컬 원본의 Git 상태와 변경 전 기준을 기록하고 기존 사용자 변경을 구분한 뒤 원본에서 수정한다. 제출까지 포함되면 같은 저장소에서 열린 PR과 변경 브랜치를 확인한다. 기본 base는 `reflect-review`다. 같은 개선의 PR은 담당자와 상태를 확인해 재사용하며, 변경 브랜치 준비와 원격 기준 확인은 submit-improvement에 맡긴다. 수정용 worktree로 원본을 대체하지 않는다.
3. 기존 지침의 수정·삭제는 직접 수행한다. 규칙은 소유한 스킬에서 관리하고 다른 스킬은 참조한다. 변경한 기능과 책임을 skill-refer.md에도 갱신한다.
4. 새 스킬이 필요하면 반복 문제, 기존 스킬 수정으로 해결하기 어려운 이유, 기대 결과와 범위를 [namuk-skillcreator](../namuk-skillcreator/SKILL.md)에 위임한다. 생성 담당자가 필요성을 재검토하도록 세부 설계를 미리 고정하지 않는다. 생성 담당자는 기능 문서 갱신과 검증 결과까지 반환한다.

## 검증 결과와 후속 작업

작성 담당자는 형식·참조·diff와 기능 문서의 일치를 확인한다. 의미와 동작을 유지하는 오타·링크·표현 수정은 기본 검사로 마친다. 새 스킬 또는 동작·자동 선택·호출 흐름·책임 경계 변경은 [verify-improvement](../verify-improvement/SKILL.md)의 기준으로 검증 대상인지 구분한다. 현재는 실제 비교를 실행하지 않고 제출 흐름으로 진행한다.

reflect 담당자는 비교 결과가 없으므로 개선이 검증됐다고 표시하지 않는다. 검증을 생략한 이유와 영향을 받는 동작을 제출 기록에 남긴다.

제출 범위의 작업이면 [submit-improvement](../submit-improvement/SKILL.md)를 실행할 별도 서브에이전트에 제출을 맡긴다. 소스·worktree, origin, base와 head, 변경 파일, 개선 근거와 이유, 기본 검사 기록과 생략한 비교 검증을 전달한다. PR 대상 브랜치에 미리 병합하지 않는다. 제출 담당자가 작업하는 동안 같은 worktree를 수정하지 않는다. 별도의 수정안 승인 단계는 두지 않되 사용자 제한을 우선한다.

담당자는 결과를 회수해 변경 요약, 작업 위치, 검증과 한계, 제출했다면 확인된 PR URL을 반환한다. 막혔다면 완료 단계와 장애를 알린다. 로컬 수정·검증만 요청됐다면 해당 범위에서 마친다.
