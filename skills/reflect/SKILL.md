# Reflect

현재 대화의 경험을 다음 작업에 적용하도록 플러그인을 개선한다. 채팅에서 수정안 승인을 기다리지 않고 로컬 소스에서 변경·검증한 뒤 PR을 만들어 사용자가 나중에 검토하게 한다. 사용자가 이번 작업에서 정한 제한은 우선한다.

## 소스와 범위

- 로컬 소스 저장소: `D:\Plugin\namuk-process`
- 원격 저장소: `https://github.com/skadnr3126/namuk-process.git`
- PR 대상 브랜치(base): `reflect-review`

수정 전 Git 최상위 경로, origin, `.codex-plugin/plugin.json`의 `name: namuk-process`를 확인한다. 경로가 없거나 다른 저장소이면 정확한 경로를 요청한다. 설치본이나 캐시를 소스로 대체하거나 수정하지 않는다.

## 실행 담당

메인 에이전트는 개선 신호를 발견하면 서브에이전트 하나에 이 스킬의 실행을 맡긴다. 사용자 요청과 제한, 관련 대화와 피드백, 관찰 결과, 소스 경로, 변경 가능한 범위를 전달한다. 관찰과 해석을 구분하고, 개선 방향을 이미 정했다면 그 이유도 전달한다.

서브에이전트는 별도 worktree와 변경 브랜치를 소유하고 개선 판단·수정부터 PR 제출까지 담당한다. 검증은 verify-improvement에 따라 맥락을 상속하지 않는 새 서브에이전트에게 맡긴다. 이미 이 작업을 위임받았다면 reflect나 제출을 다시 위임하지 않는다. 다른 작업자도 같은 저장소를 사용함을 전제로 타인의 변경을 되돌리지 않는다.

메인은 위임한 파일과 브랜치를 동시에 수정하지 않고 독립적인 사용자 작업을 계속한다. 같은 개선에 기존 담당자가 있으면 새로 생성하지 말고 그 담당자에게 맥락을 추가한다. 서브에이전트는 완료 시 변경 요약, worktree·브랜치, 검증 결과와 한계, 확인된 PR URL을 반환한다. 막혔다면 완료 단계와 장애를 반환한다. 메인은 결과를 회수해 사용자에게 알리며, 완료 전에 제출됐다고 보고하지 않는다.

서브에이전트를 사용할 수 없으면 그 제한을 알리고 메인이 같은 작업 분리와 제출 절차를 수행한다.

## 개선 근거

명시적인 요청뿐 아니라 현재 대화에서 개선 근거가 드러나면 실행한다. 사용자 발언, AI가 시도한 행동, 실제 결과를 구분하고 어떤 스킬의 어떤 판단이 달라져야 하는지 찾는다. 확인되지 않은 효과를 성공 사례로 단정하거나 일회성 프로젝트 요구를 보편적 규칙으로 만들지 않는다.

기존 내용의 수정·삭제나 필요한 스킬 추가가 대상이다. 구체적 근거가 없으면 변경과 PR을 만들지 않는다. 간접적으로 발견한 개선은 진행 중인 사용자 작업의 자연스러운 마무리 지점에서 처리한다. reflect가 만든 제안 자체를 새 근거로 삼아 재귀적으로 실행하지 않는다.

## 변경과 검증

1. 관련 지침과 참조 파일을 읽고 열린 PR에 같은 개선이 있는지 확인한다. 같은 건의 PR은 해당 브랜치를 확인해 갱신하고 중복 생성하지 않는다.
2. 작업 트리 상태를 확인하고 최신 `origin/reflect-review`에서 별도 Git worktree와 `reflect/<주제>-<고유값>` 브랜치를 만든다. 기존 PR을 이어가는 경우 담당자가 사용 중인지 확인하고 해당 작업 전용 worktree를 재사용한다. 모든 수정·검증·Git 명령은 담당 worktree를 명시해 실행한다. 사용자 변경을 되돌리거나 이번 커밋에 포함하지 않는다. fetch가 실패하면 오래된 기준으로 진행하지 말고 막힌 지점을 알린다. 대상 브랜치가 없으면 생성 기준을 확인하고, main으로 임의 대체하지 않는다.
3. 근거에 맞는 최소 변경을 한다. 규칙을 여러 스킬에 복사하기보다 소유한 스킬을 고치고 필요한 곳에서 참조한다.
4. 변경 출발 커밋과 변경본 스냅샷을 고정하고 [verify-improvement](../verify-improvement/SKILL.md)에 검증을 위임한다. 구조 검사와 기존본·변경본 비교는 그 스킬이 담당한다. 검증 담당에게 작성자의 성공 주장이나 대화 이력을 넘기지 않는다.

추가 수정, 재검증, 제출 여부는 verify-improvement의 결과와 중단 기준을 따른다. 개선 효과가 입증되지 않았는데 검증 완료로 표시하지 않는다.

## PR 제출로 연결

변경과 검증을 마치면 같은 담당 서브에이전트가 [submit-improvement](../submit-improvement/SKILL.md)를 읽고 같은 worktree에서 제출을 이어간다. 별도의 제출 담당 에이전트나 수정안 승인 단계는 두지 않는다.

작업한 소스 또는 worktree 경로, 원격 저장소, base와 head, 이번 변경 파일 목록을 전달한다. 현재 대화에서 확인한 개선 근거, 변경 이유, 검증 명령·입력·예상 결과·실제 결과, 미확인 항목도 함께 전달한다. PR 본문 작성과 커밋·push·제출 확인은 submit-improvement가 담당한다.
