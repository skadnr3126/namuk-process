# 플러그인 개선 검증

같은 요청에서 변경본의 개선과 회귀를 확인한다. 문서 정돈이나 형식 검사만으로 개선을 판정하지 않는다. 전체 책임 경계는 [skill-refer.md](../../skill-refer.md)를 따른다.

현재 합의한 검증 경계와 흐름을 아래에 정리한다. 실행 환경의 플러그인 격리 방법, 평가자 수와 판정 결합 방식은 추가 구체화 대상이다. 실행 시 확인되지 않은 조건을 충족한 것으로 간주하지 않는다.

## 입력과 역할

변경 담당자는 확인된 소스 경로, 고정된 기존본·변경본 식별자, 변경 파일, 사용자 요구와 입력 자료, 허용 범위를 전달한다. 기존본은 변경 출발 커밋을 사용한다. 미커밋·미추적 파일은 제출 대상만 스냅샷으로 보존하고 목록과 해시를 기록한다. 검증 후 내용이 바뀌면 결과를 재사용하지 않는다.

검증 조정 담당은 대화 이력을 상속하지 않는 새 서브에이전트로 생성한다. `fork_turns="none"`을 사용하고 작성자의 성공 주장이나 선호하는 해결안을 전달하지 않는다. 이미 검증 담당이면 같은 역할로 다시 위임하지 않는다.

실행 담당과 평가 담당을 분리한다. 실행 담당은 사용자 요청을 수행하고, 평가 담당은 익명화된 결과와 필요한 실행 기록을 기준으로 판단한다. 자신이 만든 결과를 스스로 평가하지 않는다. 독립성과 맥락 분리가 불가능하면 판단 불가로 반환한다.

## 비교 흐름

1. 저장소 신원과 두 버전을 확인한다. 기존본과 변경본에 각각 검증용 worktree를 준비하고 작업 담당자의 worktree와 설치 캐시는 수정하지 않는다. 모든 명령의 작업 경로를 명시한다.
2. 결과를 보기 전에 동일한 테스트 요청과 관찰 기준을 정한다. 요구를 대표하는 사례와 관련 회귀 사례를 포함한다. 자동 선택 변경이면 발동·비발동 상황을 확인한다. 새 스킬이 없는 기존본도 같은 사용자 요청을 수행한다.
3. 각 환경에 목표 버전의 플러그인만 적용됐는지 확인한다. 설치본이 함께 적용되면 시험 환경에서 제외하고 적용 상태를 확인한다. worktree 생성만으로 격리됐다고 판단하지 않는다. 격리를 확인하지 못하면 비교를 중단하고 판단 불가로 반환한다. 영구적인 사용자 설치 설정을 임의로 바꾸지 않는다.
4. 두 실행은 각각 새로운 맥락 없는 에이전트가 맡는다. 모델·도구·권한·입력 조건을 맞추고 해당 버전과 사용자 요청·제한만 전달한다. 다른 실행의 결과, 작성자 주장, 정답이나 평가 기준은 주지 않는다. 스킬 파일을 명시적으로 읽힌 시험을 자동 선택 검증으로 보고하지 않는다.
5. 검증 조정 담당은 산출물과 필요한 실행 기록에서 버전을 드러내는 경로·라벨·변경 설명을 제거하고 A/B로 제공한다. 실제 동작의 증거는 보존한다. 별도 평가 에이전트는 사전에 정한 기준과 원래 사용자 요구로 평가한다. 기존본·변경본의 대응은 평가가 끝난 뒤 공개한다. 익명화가 불가능하면 한계를 기록한다.
6. manifest, frontmatter, 이름·경로, skill-refer.md와 실제 지침의 일치, diff와 사용 가능한 validator 결과를 확인한다. 구조 검사와 행동 비교 결과는 구분한다.

시험 중 실제 원격 push·PR 생성·병합·설치 업데이트는 하지 않는다. 필요하면 로컬 시험 저장소나 기록용 대체 도구를 쓰고 실제 전송은 미검증으로 남긴다. reflect·submit-improvement를 시험하더라도 시험 제한이 우선하며 재귀적 개선·제출을 시작하지 않는다.

## 판정과 반환

입력·관찰 기준·두 결과·실행 기록·버전과 해시·환경·재현 방법·검사 결과·한계를 남긴다. 판정은 `개선 확인`, `차이 없음`, `회귀 발견`, `판단 불가`로 구분한다. 승자를 강제로 고르지 않는다. 일부 사례의 개선이나 한 번의 비교를 일반적인 성능 향상으로 주장하지 않는다.

검증 담당자는 근거와 판정, 추가 개선 여지, 검증 worktree의 경로와 상태만 반환한다. 소스 수정·되돌리기·병합·PR 제출을 수행하거나 제출 스킬을 호출하지 않는다. 채택·수정·미채택과 제출 여부는 변경 담당자가 결정한다. 기존본이 더 낫다면 이번 변경을 채택하지 않고 사용자 변경과 검증 근거는 보존한다.

추가 수정은 변경 담당자가 수행하고 새 스냅샷으로 재검증한다. 자동 수정·재검증은 한 차례까지 수행한다. 여전히 회귀하거나 판단할 수 없으면 결과를 알리고 중단한다. 차이가 없으면 개선을 주장하지 않고 별도 변경 목적의 충족 여부를 판단한다. 미검증 초안 제출은 사용자가 명시한 경우에만 한계를 표시해 진행한다. 타인의 파일을 포함한 정리나 강제 삭제는 하지 않는다.
