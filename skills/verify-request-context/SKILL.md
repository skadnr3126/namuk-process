# 요청과 실제 맥락의 적합성 검증

요청을 실제 상황에서 실행할 수 있는지, 실행 전에 확인할 전제와 결정이 있는지 판단한다. 코드가 존재한다는 이유만으로 요청이 타당하거나 부당하다고 결론 내리지 않는다.

## 관련 맥락 조사

요청과 대화에서 대상·원하는 변화·완료 기준을 파악한다. 사용자 의도가 불분명한 부분과 조사로 확인할 사실을 구분한다. 의도가 비어 있어도 그 답과 무관한 조사는 진행한다.

관련 설정과 파일, 현재 동작, 실행 환경, 설계 근거를 필요한 범위만 직접 확인한다. 코드상 확인한 동작과 실제 실행으로 관찰한 동작을 구분하고, 설계 이유가 기록돼 있지 않으면 추측으로 표시한다. 확인할 수 없는 환경은 한계로 남긴다.

작은 변경은 관련 기능과 기존 패턴을 중심으로 확인한다. 구조를 바꾸는 요청은 영향을 받는 호출부·데이터·사용 흐름까지 넓힌다. 현재 코드가 이번 요청에도 적용되는지 확인하며, 코드가 없는 새 설계에는 존재하지 않는 근거를 만들어내지 않는다.

## 요청과 대조

- 요청이 전제한 현재 상태가 조사한 사실과 맞는지 확인한다. 다르면 관찰 조건과 근거를 설명한다.
- 원하는 변화가 기존 구조와 환경에서 가능한지, 관련 제약이나 영향 때문에 추가 결정이 필요한지 살핀다.
- 기존 설계와 충돌한다면 충돌과 영향을 설명한다. 기존 설계를 바꾸려는 요청일 수 있으므로, 충돌만으로 요청을 거절하거나 기존 구조에 맞게 목표를 바꾸지 않는다.
- 기존 패턴으로 정할 세부사항과 사용자가 선택해야 할 방향을 구분한다. 조사로 알 수 있는 파일명·구현 방법은 사용자에게 요구하지 않는다.

요청을 검증하기 위한 조사와 구현 결과를 검사하는 테스트를 구분한다. 필요한 동작 확인은 할 수 있지만, 이 검증을 코드 수정이나 전체 테스트 실행으로 확대하지 않는다.

## 판단과 다음 행동

요청과 관련된 확인 사실·근거, 영향을 주는 제약, 남은 결정을 간단히 전달한다. 전제가 맞고 실행할 맥락이 충분하면 기존 작업 흐름으로 이어간다. 사실 확인이 남으면 조사를 계속하거나 확인 불가의 범위를 밝힌다.

결과 방향을 바꿀 선택은 영향과 함께 사용자에게 묻고, 그 선택에 의존하는 실행만 보류한다. 접근할 수 없는 코드나 환경을 확인된 것처럼 취급하지 않는다. 조사 범위 밖의 영향이 없다고 단정하지 않는다.
