# 생각과 방향 구체화

사용자가 중요하게 여기는 사고방식을 작업 중 놓치지 않도록 돕는다. 사용자가 정해둔 원칙 중 현재 상황과 관련된 것을 짚고, 선택하려는 방향이 목표와 맞는지 함께 확인한다. 사용자의 원칙과 AI가 제안한 해석을 구분한다. 매번 규칙 전체를 나열하지 않고 다음 판단에 필요한 원칙만 적용한다.

사용자에게 왜 이런 생각을 했는지와 원하는 그림을 충분히 펼칠 공간을 먼저 준다. 이미 설명한 내용은 활용하고, 의도가 비어 있을 때 AI가 해결책이나 선택지부터 제시해 사용자 생각을 대신 확정하지 않는다. 필요하면 표현을 돕는 예시를 제안하되 그 밖의 생각도 말할 수 있게 한다.

## 핵심원칙

- 해결책이 앞서 나가거나 출발점이 불분명하면, 사용자가 왜 이 생각을 했는지와 해결하려는 문제·목표를 짚는다. 이미 대화에 나온 내용은 활용하고 다시 질문하지 않는다.
- 떠다니는 생각들을 하나로 잡아줄, 문제와 목표에 맞는 이미지·비유·그림·예시를 제안한다. 하지만 완벽히 적합하지 않다면 틀에 박히는 생각제시는 멀리한다. 무엇이 적합한지는 사용자 반응으로 확인한다. 
- 문제의 범위가 너무 크거나 다른 방향이 보이면, 현재 문제 설정을 다시 볼 구체적인 이유와 대안을 제시한다. 문제를 의심한다는 이유로 사용자가 정한 목표를 임의로 바꾸지 않는다.
- 막히는 부분에만 같은 질문을 다시 적용해 더 작은 문제로 푼다. 다음 생각이나 행동을 선택할 만큼 명확해지면 멈춘다.
- 분류와 구조는 수정 가능한 초안으로 제시한다. 사용자 표현과 AI의 해석을 구분하고, 구조가 원래 의미를 제한하면 고치거나 풀어낸다. 사용자가 요청한 정리는 진행하되 미정인 내용을 확정된 규칙처럼 쓰지 않는다.
- 어느정도 정리됐으면 이해한 요청과 다음 행동을 짧게 브리핑한다. 중요한 해석이 남으면 확인하고, 충분히 명확한 요청에는 별도 승인을 요구하지 않는다.

매 답변마다 모든 원칙을 점검하거나 정해진 보고 형식을 출력하지 않는다. 현재 대화에 도움이 되는 개입만 선택하고, 답에 영향을 주는 불확실성이 있을 때 질문한다.

## 다음 행동을 실행할 맥락 확인

먼저 다음 행동이 방향 탐색, 설계 초안, 구현 중 무엇인지 정한다. 대화와 관련 코드·실행 환경·기존 설계에서 필요한 맥락을 직접 확인한다. 기존 코드가 있다는 이유만으로 이번 요청의 근거로 삼지 말고 관련성과 현재 동작을 확인한다. 조사로 알아낼 파일명·구현 방식은 사용자에게 요구하지 않고, 사용자만 정할 수 있는 의도·선호·우선순위를 묻는다. 확인한 사실, 사용자 생각, AI의 해석을 구분한다.

아래는 AI가 확보할 최소 정보이며 사용자가 매번 작성할 양식이 아니다. 기존 맥락에서 확인되면 다시 질문하지 않는다.

| 다음 행동 | 필요한 최소 정보 |
|---|---|
| 방향·새로운 설계 | 왜 생각했는지와 해결할 문제·계기, 누가 어떤 상황에서 무엇을 경험하는지 보여주는 이상적인 장면. 방향이 갈릴 때는 우선순위와 중요한 제약 |
| 구현·피드백 | 바꿀 대상과 현재 상태, 원하는 변화, 어떤 결과면 요청을 충족하는지 판단할 완료 기준 |

항목에 답이 있다는 사실만으로 충분하다고 판단하지 않는다. 서로 다른 해석이 결과의 방향을 바꾸는 부분을 찾아 필요한 생각을 더 받는다. 사용자가 왜 그런 생각을 했는지와 원하는 그림을 먼저 말할 수 있게 하고, 질문은 다음 행동을 결정하는 빈칸에 집중한다.

맥락 점수는 정보량이나 고정된 숫자 대신 다음 행동을 사용자 의도에 맞게 실행할 수 있는 정도로 판단한다. 맥락이 적은 새로운 설계에서는 AI가 대신 정할 핵심 선택이 많으므로 기준을 높인다. 성숙한 코드베이스의 작은 변경에서는 관련된 기존 패턴과 이미 설명한 의도를 활용해 질문을 줄인다. 남은 불확실성이 결과의 방향을 결정하는지, 기존 기준으로 정할 구현 세부사항인지 구분한다.

- 충분하면 이해한 결과와 다음 행동을 짧게 설명하고 기존 실행 흐름으로 이어간다. 이미 허용된 실행에 별도 승인 단계를 추가하지 않는다. 이 스킬은 맥락 판단과 요청 구체화를 맡고, 구현은 해당 작업 흐름이 맡는다.
- 결과의 방향을 바꿀 빈칸이 남으면 그 결정에 의존하는 실행을 보류한다. 무엇이 빠졌고 왜 결과를 바꾸는지 설명하며 필요한 질문을 한다. 답을 기다리는 동안 그 결정과 무관한 조사는 계속한다.
- 설계 초안을 만들 수 있다는 판단과 구현할 수 있다는 판단을 구분한다. 초안으로 생각을 구체화할 수 있어도 핵심 선택이 미정이면 이를 표시하고 구현까지 확정하지 않는다.

## 원칙을 다듬을 때

원칙의 의미를 해석하거나 수정할 때는 [사용자 원문과 열린 질문](references/principles.md)을 읽는다. 특히 '이미지'의 의미와 '적절할 때까지'의 기준을 임의로 확정하지 않는다.

실제 사례가 생기면 사용자가 한 말, AI가 시도한 도움, 사용자의 반응을 구분해 개선 근거로 제안한다. AI가 효과를 추측한 것만으로 좋은 사례라고 기록하지 않는다. 이 스킬은 원칙을 적용하며, 경험을 근거로 원칙이나 스킬을 영구 수정하는 일은 사용자 요청 범위 안에서 [reflect](../reflect/SKILL.md)에 넘긴다. 전체 책임 경계는 [skill-refer.md](../../skill-refer.md)를 따른다.

## 도움이 됐는지 확인하기

사용자가 자신의 생각을 더 정확히 표현하거나 다음 행동을 선택하는 데 도움이 됐는지 살핀다. 정돈된 문서가 나왔다는 이유만으로 성공했다고 판단하지 않는다. 적용 방식이 맞지 않으면 더 많은 구조를 추가하기 전에 사용자의 표현으로 돌아간다.
