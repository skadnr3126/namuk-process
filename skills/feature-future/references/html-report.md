# HTML 리포트 구성

사용자가 별도 산출물을 요청했고 그 요청에 따라 HTML을 만들 때만 적용한다. 사용자가 지정한 형식과 범위를 우선한다. 대화가 복잡하다는 이유만으로 리포트를 생성하지 않는다. 사용자에게 필요한 판단을 먼저 보여주고 상세 구현은 접거나 별도 구역으로 둔다.

## 정보 구성

사용자의 목적과 요청 범위에 필요한 항목만 고르고 다음 구성을 합치거나 줄인다. 모든 섹션이나 상태 보고를 채울 필요는 없다.

1. **변경 요약:** 기능의 목적, 변경 전후 동작, 중요한 결정과 영향. 파일 목록은 핵심 변경으로 제한한다.
2. **시스템 흐름:** 진입점, 모듈의 책임과 연결, 데이터·제어 흐름, 상태 소유권과 생명주기, 지켜야 할 조건. 도움이 되면 변경 전후 구조나 데이터 흐름을 시각화한다.
3. **변경과 조사 안내:** 다음 변경의 수정 위치, 관련 호출부·테스트, 실패 시 확인할 로그·저장 데이터와 관찰 방법. 필요할 때 조사할 내부 구현은 상세 영역에 배치한다.
4. **설계 평가:** 좋은 결정과 우려, 확보하거나 제한한 미래의 선택권, 개선의 이점·비용·필요 조건. 사실·추론·견해·미확인을 구분한다.
5. **판단 사례와 다음 단계:** 실제 변경에 맞는 짧은 사례와 판단 근거, 기능 검증 상태, 제공한 이해 지원과 이해 확인 여부, 근거 있는 다음 단계 권고.

## 탐색과 추적

- 상단에 핵심 요약을 두고 긴 리포트에는 섹션 탐색 메뉴를 제공한다.
- ‘지금 알아야 할 것 → 변경할 때 찾을 것 → 필요할 때 조사할 것’ 순으로 정보를 배치한다.
- 코드 블록, 파일 경로, 함수·타입 이름, 코드 위치와 테스트 근거를 가까이 둔다. 실제로 열 수 있는 대상에만 링크한다.
- 추가·수정·삭제나 중요도의 구분은 글로도 표시하고 색에만 의존하지 않는다.
- 상세 설명은 접고 펼칠 수 있게 하되 핵심 조건과 미검증 상태를 숨기지 않는다.

생성 후 실제 브라우저에서 요약·탐색·상세 펼침과 코드 경로의 가독성을 확인한다. 실행할 수 없는 확인은 미확인으로 남긴다. 완성한 HTML의 위치를 사용자에게 전달한다.
