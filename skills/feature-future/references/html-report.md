# HTML 리포트 구성

사용자가 별도 산출물을 요청했고 그 요청에 따라 HTML을 만들 때만 적용한다. 요청한 형식과 범위를 우선한다. 현재 미션과 중요한 설계 판단을 먼저 보여주고, 판단을 뒷받침하는 상세 자료는 접거나 별도 구역으로 둔다.

## 정보 구성

대화와 요청 범위에 필요한 항목만 고른다. 모든 항목을 채우거나, 미정인 결정을 리포트를 위해 확정하지 않는다.

1. 사용자가 제시한 미션, 관련된 사람과 상황, 왜 중요한지와 기대하는 변화. 사용자 표현과 제안한 해석을 구별한다.
2. 논의 중인 설계 선택과 대안. 같은 사용 상황에서 예상하는 행동 변화, 판단 기준, 이점과 불리한 점을 비교한다.
3. 지금 제공하는 가치와 다음 변경의 선택권. 구체적인 다음 변경 사례, 되돌리기 어려운 선택, 구조 투자와 제공 지연의 비용을 설명한다.
4. 현재 추천과 이유, 사용자가 결정한 내용과 미정인 내용. 추천을 바꿀 증거와 아직 확인하지 않은 가정을 남긴다.
5. 다음 확인과 관찰 방법. 구현 검증 결과와 실제 사용에서 얻은 성과 근거를 구별한다. 미실행 제안은 결과처럼 표시하지 않는다.

## 탐색과 근거

- 상단에 현재 판단을 요약하고 긴 리포트에는 섹션 탐색 메뉴를 둔다.
- 설계 대안은 같은 기준으로 비교한다. 도표는 선택과 결과의 연결을 읽기 쉽게 할 때 사용한다.
- 대화에서 확인한 사실, 자료의 근거, 가정과 미확인을 구별한다. 출처와 코드 위치는 해당 판단 가까이에 연결한다.
- 코드 흐름은 설계 판단에 필요한 만큼만 넣는다. 상세 설명을 접더라도 중요한 제약과 미확인 상태는 보이게 둔다.
- 추천·합의·미정의 구분을 글로 표시하고 색에만 의존하지 않는다.

생성 후 실제 브라우저에서 요약, 탐색, 상세 펼침과 본문의 가독성을 확인한다. 실행할 수 없는 확인은 미확인으로 남긴다. 완성한 HTML의 위치를 사용자에게 전달한다.
