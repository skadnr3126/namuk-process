# 궁극적 목표
궁극적인 목표

새로운 기능을 지속적으로, 예측 가능하게, 자신 있게 추가할 수 있는 코드베이스를 유지하는 것.

기능을 추가하는 것은 현재의 가치를 만드는 행위지만, 동시에 기존 코드에 새로운 의존성과 제약을 만들 수 있다.

따라서 개발자는 두 가지 가치를 함께 관리해야 한다.

Feature: 현재 필요한 기능을 구현하여 가치를 만든다.

Future: 앞으로 새로운 기능을 추가하거나 기존 기능을 변경할 수 있는 선택권을 유지한다.

좋은 코드는 단순히 현재 기능이 올바르게 작동하는 코드가 아니다.

새로운 요구사항이 들어왔을 때 변경할 위치와 영향 범위를 예측할 수 있고, 안전하게 변경할 수 있는 코드다.

# 방향
개발자가 통제권을 확보하기 위해 질문을 할텐데, 그 질문에 대한 답변을 내가 이해하는 방식으로 제공하기 위해 이 문서를 작성한다.
코드베이스 이해 높히기 위해 사용되는 대화모드, 근데 매번 같은 사항에 대해서 특정방식으로 대답하라고 하기 귀찮음, 내가 이해하는 방식을 여기에 정의해 ai가 그것을 참고해서 대답하게 하기 위해서임
[explain-execution-flow] 스킬을 참초해서 대답하면 된다.


## 별도 산출물을 요청받았을 때

기본 응답은 대화다. 리포트·문서·HTML 등 별도 산출물은 사용자가 추가로 요청했을 때만 만든다. 주제가 복잡하거나 여러 모듈에 걸친다는 이유로 자동 생성하지 않는다. 요청한 형식과 범위를 우선하며, 형식이 지정되지 않았다면 요청 목적에 맞게 선택한다.

별도 산출물 요청에 따라 HTML을 만들 때만 [HTML 리포트 구성](references/html-report.md)을 읽는다. 산출물에서도 사용자의 목적과 질문, 실제 근거와 미확인 범위를 유지한다.
