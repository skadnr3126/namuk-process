# 최종 산출물 — Feature Review HTML

## 1. 산출물의 목적

이 스킬의 최종 산출물은 **HTML 형태의 코드베이스 변경 분석 및 멘토링 리포트**다.

AI가 기능을 구현한 후 발생한 변경사항을 기존 코드베이스와 연결하여 설명하고, 개발자가 구현 내용을 이해하며 미래의 변경 가능성을 판단하도록 돕는다.

이 문서는 세 가지 목적을 가진다.

1. **변경사항의 이해:** 새롭게 추가·수정·삭제된 코드의 역할과 동작을 파악한다.
2. **시스템 맥락의 이해:** 변경사항이 기존 코드베이스와 어떻게 연결되고 영향을 주는지 이해한다.
3. **설계 판단:** 숙련된 엔지니어의 관점에서 구조적 장단점과 미래의 선택권을 평가한다.

단순한 코드 변경 기록이나 품질 검사 보고서가 아니라, 개발자의 이해도와 판단력을 높이는 학습 자료여야 한다.

---

## 2. 산출물 구성

### Section 1. Feature Overview — 변경 요약

이번 기능 구현이 무엇을 목표로 했으며 시스템에 어떤 변화를 만들었는지 설명한다.

포함할 내용:

- 기능의 목적과 주요 동작
- 구현 전과 구현 후의 차이
- 추가·수정·삭제된 파일 목록
- 중요한 기술적 결정
- 기존 시스템에 미치는 핵심 영향

가능하다면 변경 전후의 모습을 간단한 구조도와 함께 보여준다.

### Section 2. Change Details — 코드 변경사항 상세

변경된 코드를 함수, 변수, 자료구조, 로직 단위로 분석한다.

**A. 함수**

- 새로 추가된 함수
- 수정된 기존 함수
- 제거되거나 대체된 함수
- 각 함수의 책임
- 입력과 출력
- 주요 호출 관계
- 기존 기능과의 연결

**B. 변수 및 상태**

- 새롭게 도입된 주요 변수
- 변경된 상태 관리 방식
- 변수의 생명주기와 소유 주체
- 데이터 일관성과 관련된 제약

**C. 자료구조 및 데이터 모델**

- 새로 도입된 타입, 구조체, 클래스
- 기존 자료구조의 변경
- 각 필드의 역할
- 저장 형식이나 직렬화 방식의 변화
- 기존 데이터와의 호환성

**D. 주요 로직**

- 새롭게 도입된 핵심 알고리즘
- 변경된 처리 순서
- 비동기 처리 및 이벤트 흐름
- 예외 및 오류 처리
- 기존 로직과 달라진 동작

모든 작은 지역 변수나 단순한 구현 세부사항까지 나열할 필요는 없다.

**기능의 동작, 구조, 미래의 변경에 영향을 주는 요소를 우선적으로 설명한다.**

각 요소를 설명할 때 가능하면 관련 파일 경로와 코드 위치를 함께 표시한다.

### Section 3. System Integration — 기존 코드와의 연결

이번 구현이 기존 코드베이스에 어떻게 통합되었는지 분석한다.

포함할 내용:

- 변경 전의 기존 구조
- 변경 후의 구조
- 새 코드가 호출되는 진입점
- 기존 함수와 새 함수의 관계
- 데이터가 전달되는 경로
- 새로 생기거나 변경된 의존성
- 상태 및 데이터 저장 방식의 변화
- 기존 기능에 영향을 줄 가능성이 있는 부분

가능하면 다음 시각화를 포함한다.

1. **Before / After 구조 비교**
2. **데이터 흐름도**
3. **핵심 함수 호출 관계도**
4. **변경 영향 범위 지도**

이 섹션에서는 단순히 무엇이 추가되었는지보다 **새로운 코드가 기존 시스템 안에서 어떤 위치를 차지하는지** 설명하는 것이 중요하다.

### Section 4. Mentor's Review — 멘토의 견해

대규모 서비스 개발과 유지보수에서 중요한 설계 원칙을 고려하는 시니어 엔지니어의 관점에서 변경사항을 평가한다.

#### A. 잘된 설계 결정

- 적절한 책임과 경계
- 명확한 데이터 흐름
- 불필요한 결합을 방지한 부분
- 기존 구조를 효과적으로 재사용한 부분
- 향후 변경을 쉽게 만드는 결정

왜 좋은 결정인지 구체적인 근거를 제시한다.

#### B. 우려되는 설계 결정

- 변경 비용을 높이는 의존성
- 책임이 불명확한 함수나 모듈
- 불필요하게 복잡해진 구조
- 잠재적인 상태 관리 문제
- 테스트나 디버깅을 어렵게 만드는 요소

막연한 우려가 아니라 실제 코드와 구체적인 변경 시나리오에 근거하여 분석한다.

#### C. Feature / Future 분석

현재 기능을 위해 어떤 설계 결정을 내렸고, 그 결정이 미래의 선택권에 어떤 영향을 주는지 평가한다.

- 확보한 선택권
- 감소한 선택권
- 아직 남겨둔 선택권
- 변경 비용이 높아질 수 있는 지점
- 미래에 구조 개선이 필요해지는 조건

미래에 일어날 수 있는 모든 상황에 대비하는 것은 목표가 아니다.

#### D. 멘토의 제안

개선이 필요한 경우 다음 내용을 제시한다.

- 어떤 문제를 해결하려는가?
- 어떤 개선 방법이 가능한가?
- 개선 시 얻는 이점은 무엇인가?
- 개선에 필요한 비용과 복잡성은 무엇인가?
- 지금 개선할 가치가 있는가?
- 당장 개선하지 않아도 되는 이유는 무엇인가?

중요도와 시급도를 구분하며, 불필요한 리팩터링을 권장하지 않는다.

### Section 5. Readiness & Next Steps — 다음 단계 판단

개발자가 다음 기능으로 넘어가도 되는지 판단할 수 있도록 정리한다.

#### 이해도 관점

이번 구현에서 반드시 이해해야 할 핵심 개념과 동작을 요약한다.

특히 다음 질문에 답할 수 있도록 한다.

- 새로운 기능은 어디서 시작되고 어떻게 실행되는가?
- 핵심 데이터는 어떻게 이동하는가?
- 변경된 함수와 모듈의 책임은 무엇인가?
- 다음 요구사항이 들어오면 어느 부분을 수정해야 하는가?
- 어떤 불변 조건을 유지해야 하는가?

#### 검증 관점

- 수행된 테스트와 그 결과
- 아직 검증되지 않은 동작
- 기존 기능에 대한 회귀 위험
- 추가 확인이 필요한 부분

테스트를 수행하지 않았다면 수행한 것처럼 작성하지 않는다.

#### 최종 권고

다음 네 가지 중 적절한 방향을 제시한다.

1. **진행:** 현재 구조를 유지하고 다음 기능을 구현한다.
2. **추가 이해:** 특정 부분을 더 이해한 후 진행한다.
3. **구조 개선:** 중요한 구조 문제를 개선한 후 진행한다.
4. **추후 개선:** 개선 사항을 기록하되 현재는 진행한다.

최종 권고는 근거와 함께 제시한다.

## 3. HTML 설계 원칙

### A. 읽기 쉬운 시각적 구조

긴 텍스트 문서가 아니라 개발자가 정보를 탐색하고 이해하기 쉬운 리포트를 만든다.

권장 요소:

- 상단 요약 대시보드
- 섹션별 탐색 메뉴
- 변경사항을 구분하는 시각적 표시
- 코드 블록과 파일 경로
- 변경 전후 비교
- 구조도 및 데이터 흐름도
- 중요도별 멘토 코멘트
- 접고 펼칠 수 있는 상세 설명

### B. 정보의 계층화

가장 중요한 내용을 먼저 보여주고, 상세한 정보는 필요할 때 확인하도록 한다.

정보의 기본 계층은 다음과 같다.

**기능 전체 → 변경된 구성요소 → 주요 코드 → 상세 구현**

### C. 사실과 견해의 구분

리포트에서 다음 내용을 명확하게 구분한다.

- **확인된 사실:** 실제 코드와 변경 내역에서 확인된 내용
- **분석 및 추론:** 코드의 동작과 영향에 대한 분석
- **멘토의 견해:** 설계 평가, 우려, 개선 제안
- **미확인 사항:** 추가 검증이 필요한 가정이나 정보

### D. 코드 근거와 추적 가능성

중요한 설명은 실제 코드와 연결되어야 한다.

가능하면 다음을 표시한다.

- 파일 경로
- 함수 및 타입 이름
- 코드 위치
- 관련 변경 내역
- 근거가 되는 테스트

개발자가 설명을 읽은 후 실제 코드로 쉽게 이동할 수 있어야 한다.

### E. 불필요한 정보 최소화

모든 코드를 분석 결과에 나열하지 않는다.

이해와 설계 판단에 중요하지 않은 단순 변경은 요약하고, 핵심적인 부분은 깊게 설명한다.

## 4. 산출물 생성 절차

1. 기능 구현의 변경 범위 확인
2. 변경된 파일, 함수, 변수, 자료구조, 로직 분석
3. 기존 코드베이스와의 연결 관계 조사
4. 주요 데이터 흐름과 의존성 정리
5. 변경 전후 구조 비교
6. Feature / Future 관점의 멘토 분석
7. 검증 상태와 위험 정리
8. 최종 HTML 리포트 생성

필요한 경우 개발자와 대화를 통해 추가적인 분석을 진행한다.

---

## 5. 최종 산출물의 성공 기준

리포트를 읽은 개발자가 다음 사항을 이해할 수 있어야 한다.

- 무엇이 변경되었는가?
- 왜 그렇게 변경되었는가?
- 새로운 함수, 변수, 자료구조는 어떤 역할인가?
- 변경된 코드가 기존 시스템과 어떻게 연결되는가?
- 데이터와 제어 흐름은 어떻게 달라졌는가?
- 이번 구현으로 어떤 선택권이 확보되거나 제한되었는가?
- 멘토는 어떤 부분을 좋게 평가하고 어떤 부분을 우려하는가?
- 다음 기능으로 넘어가기 전에 무엇을 확인하거나 개선해야 하는가?

**최종 목표:**

AI가 구현한 기능을 단순히 작동하는 코드로 남기는 것이 아니라, 개발자가 이해하고 미래의 변경을 판단할 수 있는 지식으로 전환한다.
